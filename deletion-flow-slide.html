Deleting elements and wires

Selection IDs flow to the controller; Circuit removes attached topology and repairs node bookkeeping.

model action guard / decision
1
Select what to remove
CircuitCanvas → SelectionManager
selectElement(id, additive)Component click; Shift/Ctrl adds or toggles selection.
onSelectPoint(...) → selectWire(...)Wire click selects one segment; double-click selects connected wires.

SelectionManager stores element IDs and wire IDs. Its change callback redraws selection highlighting.

2
Invoke Delete
Toolbar button or keyboard
EditorToolbar → onDelete.run()Callback is wired to controller::deleteSelected.
EditorWindow → controller.deleteSelected()Delete or Backspace key path.
3
Dispatch selected IDs
EditorController.deleteSelected()
If drawingWire → return. If no selected IDs → return.

Read getSelectedElements() and getSelectedWires().

Element IDs → onElementDeleted(id) → Circuit.removeElement(id)

Wire IDs → Circuit.removeWireSegments(wireIds)

4A
Element removal cascades through connected nodes
Circuit.removeElement(id)
Seed attached segments

Scan wires; belongsTo(port, id) checks whether a Port owner is the deleted element.

→
BFS through PointNodes

Queue segments; visit each endpoint node's getConnectedSegments(). A Port endpoint stops traversal.

→
Remove and repair

wireSegments.removeAll(doomed); call node removeSegment(...); prune empty nodes.

Unknown element ID returns false. The BFS uses a set to avoid processing a segment twice.

4B
Explicit wire selection
Circuit.removeWireSegments(ids)
Remove matching IDs

Unknown and already-cascaded IDs are skipped.

→
Update endpoints

Call removeSegment(...) on connected nodes; prune nodes with no segments.

Direct wire deletion removes only the selected segment IDs; element deletion performs the connected-node cascade.

5 · Finish and refresh

selection.clear() → if changed: notifyRender() redraws the canvas, then recordChange() stores the history snapshot.

→
Updated Circuit + consistent PointNodes
